# T1 基础RAG实验与无检索对照分析

实验日期：2026-10-25（Asia/Shanghai）。本报告以本次真实模型输出为依据，不改写模型答案，不挑选重跑中最好的一次。

## 1 实验设置

评测集为固定的20条D3题，L1—L4各5条。基础RAG保持原LangChain链路：加载 → 650字符/120重叠切分 → 字符TF-IDF/64维LSA → FAISS → 向量top-5 → Context → ChatOllama。23篇资料和原模型不变，没有查询改写、混合检索、重排或路由。

两组均使用 `qwen3:4b-instruct`，模型摘要 `0edcdef34593eac1aa2be9c7d06c432dcf81945adca5eca2f27662c18f168ba0`，temperature=0.2、seed=42、num_ctx=16384、num_predict=2048。同一问题字面完全一致，每次独立对话，不向模型传入gold_answer、gold_chunk_ids或评分规则。按题号奇偶交替两组调用顺序，逐次串行运行。

RAG调用现有 `build_rag_chain`，实际top-5正文、编号、来源和拼接Context都随答案保存。无检索组不加载任何Context或工具，直接给同一问题，并要求不确定时说明不知道。为避免让无检索组因‘仅根据参考资料回答’而被强制拒答，其系统提示删除资料专用约束与引用要求。因此这是实用两种运行方式的对照，存在提示词适配差异，不宣称严格隔离了单一变量的因果效果。完整无检索提示和参数见 `t1_run_metadata.json`，RAG提示仍在原 `src/rag_chain.py`。

服务端种子和参数已记录，但不保证不同设备、服务版本间逐字复现。耗时包含首题冷启动和模型生成，不是单独检索延迟，也不是严格硬件基准。没有额外重复试验或显著性检验。

## 2 完成情况与评分口径

RAG完成20题，无检索完成20题；错误调用分别0、0；达到生成长度上限的回答分别0、0。两份JSONL均保留未经修改的原始答案及调用元数据。

答案由Codex助手逐条对照固定gold、证据摘录和实际召回后评分，未调用Qwen自评，未声称独立教师/学生人工审核。L1—L3：0=核心结论错误或未回答，1=部分正确或加入影响可信度的无依据事实，2=完成题目主要要求；L4按既有5个评分点各0/1分。不能要求模型复述所有未被问题询问的附带gold说明。汇总使用每题得分/该题满分再取平均，称‘归一化得分’，不是客观准确率或EM。逐题理由与实际答案原句保存在 `t1_answer_reviews.jsonl`。

其中RAG有1题出现超出候选编号范围的引用。批量实验直接调用与交互程序相同的LCEL生成链，保留原始答案再记录引用合法性；正常 `answer_baseline`/CLI包装层会对越界引用报错。因此‘API调用成功’不等于‘引用校验通过’，不能把这类输出算成完全有效的交互回答。

## 3 检索表现

按作业‘至少命中一个gold chunk’的口径，Hit/Recall@5为90.0%；MRR@5为0.6850。平均gold块覆盖比例为80.4%，全部gold块均召回的题数为13/20。只检索了5块，故不把MRR@5写成MRR@10。

严格chunk指标可能低估重叠片段中的等价证据：某题gold块未全部命中不自动等于回答失败；反之，任一块命中也不证明上下文完整。归因时同时查看实际正文，区分未召回关键证据、部分证据缺失与证据已到位但生成越界。无检索组没有召回结果，不给它计算检索Recall。

## 4.1 成功案例一：q002（先修课事实定位）

**问题：** 根据云南大学《数据库概论》公开慕课课程大纲，该课程要求的先修课是什么？

**参考答案：** 先修课为数据结构。依据是公开慕课课程页面，不能将它表述为完整的校内课程大纲。

**RAG关键原句（摘录，全文见逐题对照）：**

先修课是数据结构[1]

**无检索关键原句（摘录）：**

我不知道云南大学

**实际top-5：** `ynu006_p000_00088`、`ynu006_p000_00089`、`ynu007_p000_00090`、`ynu008_p000_00095`、`ynu001_p015_00026`

**Gold：** `ynu006_p000_00088`

**评分：** RAG 2/2，无检索 0/2。

**分析：** 首位召回直接包含‘本课程要求的先修课为数据结构’，模型准确给出先修关系并引用[1]。无检索组明确不知道。这个增益来自可定位的课程资料，而非模型自行猜测。

## 4.2 成功案例二：q006（跨片段比较与简单计算）

**问题：** 按2026年《本科学生课程学分认定管理规定》，转专业原专业其他课程认定到现专业选修模块，与辅修或微专业课程认定到主修选修模块，累计上限分别是多少？后者比前者多多少？

**参考答案：** 前者累计不超过10学分，后者累计不超过15学分，相差5学分；两类各自的专业教育认定上限均为5学分。转专业原通识教育选修课程直接认定，不应把这一例外混入上述‘其他课程’上限。本规定自2025级学生开始执行。

**RAG关键原句（摘录，全文见逐题对照）：**

后者比前者多**5学分**

**无检索关键原句（摘录）：**

相关政策尚未实施

**实际top-5：** `ynu010_p000_00111`、`ynu010_p000_00115`、`ynu030_p000_00197`、`ynu010_p000_00112`、`ynu012_p007_00129`

**Gold：** `ynu010_p000_00111`、`ynu010_p000_00112`、`ynu010_p000_00116`

**评分：** RAG 2/2，无检索 0/2。

**分析：** 实际召回包含学分认定第四条和第八条，模型正确给出10与15学分并算出差5学分，且保留各自专业教育5学分限制。gold中的年级适用块未召回，但题目没有询问年级，实际证据已足以完成所问核心比较；这是检索覆盖指标与任务正确性不能混同的例子。

## 4.3 失败案例一：q001（检索漏召回）

**问题：** 按软件工程2022版（2023年修订）培养方案，国内学生第一课堂需要修满多少学分？

**参考答案：** 按该版本培养方案，国内学生第一课堂需修满161.5学分。此数不含另行要求的第二课堂6学分，也不能据此认定所有毕业条件均已满足。

**RAG关键原句（摘录，全文见逐题对照）：**

资料不足。

**无检索关键原句（摘录）：**

160学分

**实际top-5：** `ynu001_p018_00029`、`ynu001_p001_00000`、`ynu001_p009_00014`、`ynu004_p007_00069`、`ynu001_p017_00028`

**Gold：** `ynu001_p008_00013`

**评分：** RAG 0/2，无检索 0/2。

**分析：** 正确答案是161.5学分。top-5主要包括方案封面、附录/辅修双学位内容及无关专业片段，未召回毕业要求页的金标块。模型没有编造，回答资料不足；就完成问题而言仍是失败。可以确定的是检索命中了相关文档却没有定位到关键正文。长标题和文档名称的词面信号可能影响了排序，但本次未做消融，不能把这一解释视作已验证因果。无检索答案160也错误，故这题没有体现答案正确性的RAG增益。

## 4.4 失败案例二：q003（检索漏召回且无检索反而答对）

**问题：** 只依据2020版《云南大学本科学生成绩与考务管理规定》，学生每学期申请缓考的课程一般不得超过几门？

**参考答案：** 一般不得超过两门。这里复述的是2020版文件，不据此断言该规则在所有后续年份均保持不变。

**RAG关键原句（摘录，全文见逐题对照）：**

答案：资料不足。

**无检索关键原句（摘录）：**

一般不得超过**2门**

**实际top-5：** `ynu012_p001_00123`、`ynu012_p002_00124`、`ynu011_p001_00117`、`ynu012_p010_00132`、`ynu012_p006_00128`

**Gold：** `ynu012_p003_00125`

**评分：** RAG 0/2，无检索 2/2。

**分析：** 正确条文为每学期一般不得超过两门，位于原文件第3页。top-5含文件封面和第2页等相近片段，未召回第3页，正文也未出现数量上限，模型遂答资料不足。无检索模型却答对两门。因此该题既是完整失败案例，也是RAG不一定优于模型已有知识的真实反例。

## 4.5 生成缺陷案例一：q009（召回到位但生成越过证据）

**问题：** 结合2026年秋季辅修和微专业通知，辅修学士学位与微专业修读证书能否视为同一种学位成果？说明两者的差别。

**参考答案：** 不能。辅修学士学位须按对应方案修满55学分以上、符合辅修学位授予条件、取得主修学士学位，并履行申请和审议程序；具体课程与最低学分仍以专业方案为准。微专业不授予学位，只能在满足培养方案及审批要求后取得修读证书。

**RAG关键原句（摘录，全文见逐题对照）：**

与主修专业学位具有同等地位

**无检索关键原句（摘录）：**

**不能视为同一种学位成果**

**实际top-5：** `ynu029_p000_00192`、`ynu030_p000_00198`、`ynu029_p000_00191`、`ynu009_p000_00108`、`ynu030_p000_00197`

**Gold：** `ynu029_p000_00192`、`ynu030_p000_00198`

**评分：** RAG 1/2，无检索 1/2。

**分析：** 两个gold块都已召回，核心‘辅修学位与微专业证书不能等同’回答正确，但模型扩写‘与主修专业学位具有同等地位’，资料未提供这一判断；又笼统称微专业课程学分不计入学位授予体系，而实际召回中的微专业通知允许部分学分认定为主修选修。这里不对学位法律地位作外部判断，只指出生成内容超出了本次证据。故记部分正确，主要归因为生成忠实度问题，不应归咎于未检索到原文。

## 4.6 生成缺陷案例二：q017（表格跨块关系读取错误）

**问题：** 假设我是软件工程学生，更想把AI和数据处理用于健康服务，而不是媒体内容创作。仅结合2026年秋季微专业通知中‘智慧医疗’与‘智能传播’的介绍，应优先了解哪个？给出理由和进一步核实事项。

**参考答案：** 要点式评分：①倾向优先了解智慧医疗，但表明是目标匹配建议，不是录取或就业结论；②用智慧医疗介绍中的AI底层算法、数据处理、医疗辅助诊断、健康大数据管理或心理危机智能预警等内容支持建议；③将智能传播的AI与新闻传播、AI创作和流量运营等方向作对照，不能说它完全不使用AI；④提醒继续核实具体课程大纲、先修要求、课表、选拔及实际项目机会，介绍不能证明每项能力一定能获得；⑤不虚构就业率、薪资、录取概率或医疗执业资格。

**RAG关键原句（摘录，全文见逐题对照）：**

0871-65931520，陈老师

**无检索关键原句（摘录）：**

可穿戴设备数据分析、电子病历处理

**实际top-5：** `ynu030_p000_00193`、`ynu030_p000_00195`、`ynu030_p000_00194`、`ynu030_p000_00196`、`ynu001_p013_00021`

**Gold：** `ynu030_p000_00194`、`ynu030_p000_00195`

**评分：** RAG 3/5，无检索 4/5。

**分析：** 推荐智慧医疗的方向合理，但把‘短视频与数字文化传播’这个独立项目写入智能传播介绍，又把智慧城市与数字治理的65931520/陈老师误配给智慧医疗。实际第4个召回块含智慧医疗电话65931540，可直接核对。两个gold块也已召回，所以错误来自生成时的表格行关联和不必要的联系信息扩写。本次五点评分中RAG为3分，无检索为4分；后者虽有未核实课程扩写，但方向推断与核实建议较合理。该比较只代表本次公开评分规则，不意味着无检索内容已全部可信。

## 5 对照结论：增益与剩余问题

事实与政策细节方面，RAG可把模型不知道的课程先修、当年GPA门槛、学分上限、申请日期等具体值送入上下文，并提供可追溯引用。与无检索相比，不能仅因答案更长或更有自信就判更好，必须核对数值、年份、资格条件和证据。

存在明确反例：q003的无检索模型答对‘一般最多两门’，RAG却因漏召回该条文而拒答。这说明模型已有知识有时足够，而不完整的检索上下文与‘仅依据资料’约束也可能压低表现。不能把RAG描述为对每题都更好。

当前主要问题包括：①相同文档标题和版本名称可能把封面/附录排在关键条款之前；②多片段、跨页规则不一定全部进入top-5；③即使证据齐全，模型仍可能扩写没有依据的政策判断；④L4建议需要区分原文约束与个人建议，文字流畅不等于证据充分；⑤无检索模型会出现‘2026尚未到来/政策未发布’等时间或可得性断言，本次没有把日期额外加入任一组提示，应在解释中保留这一限制。

后续可分别检验正文权重/查询改写、重排/跨页上下文、生成后的事实—证据核对等改进，但本次不为提高结果而修改基础链路，也不在同一测试集反复调参后挑最好结果。

## 6 复现与文件

在项目根目录激活Python 3.12的Conda环境，启动Ollama并准备原标签后执行：

```cmd
python data\eval\verify_eval_set.py
python src\run_t1_experiment.py --output-dir results\t1_rerun
```

若该次调用中断且文件绑定一致，可使用 `--resume` 续跑。脚本不会覆盖已有原始结果，不自动重试挑选答案；异常调用会原样记录。需要重新评分时，应阅读新答案、重新形成review文件，不可直接照搬本次主观评分。

- `t1_baseline.jsonl`：20条RAG原始答案、实际召回、Context、耗时和token元数据。
- `t1_no_retrieval.jsonl`：20条无检索原始答案及同类运行数据。
- `t1_run_metadata.json`：参数、模型摘要、提示与数据/代码哈希。
- `t1_answer_reviews.jsonl`：40条助手评分、理由、原始答案证据句。
- `t1_comparison.csv`、`t1_summary.json`：逐题与汇总比较。
- `t1_逐题答案对照.md`：全部问题的两组答案及评分，方便逐项人工复核。

本报告和评测集均使用大模型辅助编程与分析；未冒称学生独立完成分析。提交人应按课程学术诚信要求独立核对并形成自己的解释。
